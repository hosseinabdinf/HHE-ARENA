# HHE-ARENA completion plan

## Current baseline (2026-10-08)

- Matrix v2 is a draft with 29 implementation units and 103 benchmark variants.
- The v2 catalog contains 26 images for non-dependency-blocked packaging units; BtR, FiLIP/Rust reference, and YuX HElib remain excluded while blocked.
- The host CLI lists 435 operation choices: 183 ready, 250 deferred, and 2 blocked. Exact deferred HE/HHE targets remain gated unless selected through the bounded validation path.
- The matrix has 87 ready, 73 deferred, and 2 blocked target records across 103 variants. No catalog image has an immutable pull reference.
- The five lightweight matrix-v1 operations completed a functional run on native Linux with five valid records and zero invalid records. Preflight warnings prevent publication use.
- CI has static/schema/inventory checks, ten lightweight image smoke jobs, and a separate manual heavy-image build-only workflow. No v2 image has a published immutable pull reference.

## Current phase status

- Phase 1: consistency/schema/selector reconciliation is complete. The recommended scope is documented; freezing it still needs owner approval.
- Phases 2–3: complete for the current draft. HHE Framework packaging, schemas, inventory checks, and CI wiring are in place.
- Phase 4: all ten FFT-CBS pure-HE selectors and all three FRAST PBS profiles pass their exact bounded operations with output assertions and are ready. The temporary per-row half-spacing assertion was invalid as a standalone correctness gate and has been removed. FiLIP independent-PTX native SKE encryption passed an isolated one-operation run and roundtrip assertion; that target is ready. Remaining HHE work is intentionally deferred at the user's Pasta2 stop boundary; additional SKE runs are unnecessary for the current validation scope.
- Phase 5: blocked by strict host preflight; the current VM is virtualized and does not confirm RDTSCP, governor, or Turbo state.
- Phase 6: the release record and scope proposal are prepared; all 26 local catalog tags pass a metadata/runtime-label audit. Owner scope approval, a registry destination and credentials, immutable published digests, and archived target evidence remain open.

## Completion criteria

Every supported operation has matching matrix, catalog, and embedded-manifest selectors; a pinned compiler-free non-root image; a verified contract; and a recorded functional result. Release images have immutable digests. Publication comparisons additionally require strict host preflight, recorded provenance, and an audited security profile. Unsupported units remain visible with explicit blockers and cannot execute.

## Work order

1. **Reconcile source of truth.** Add an automated matrix/catalog/manifest consistency check, fix mismatches, align schemas with actual readiness states, and update stale status and user documentation. Keep the checks in CI. Freeze the first-release scope: recommend 26 supported units after HHE Framework packaging, with BtR, FiLIP/Rust reference, and YuX HElib explicitly unsupported until their blockers are resolved.
2. **Finish HHE Framework HE/HHE packaging.** Build pinned HElib, SEAL, and TFHE runtime images or a justified split; add concrete manifests and catalog entries; validate contracts and selectors without executing HE/HHE workloads.
3. **Expand CI.** Validate JSON schemas and cross-file relationships, build all ten lightweight images, and run bounded safe jobs through JSONL validation and reporting. Build heavy images in a separate workload-free job. **Complete.**
4. **Validate deferred HE/HHE choices.** Exact selector dry-runs are complete. Continue bounded functional validation only on suitable hardware and within the user's stop boundary for heavy HHE schemes. Promote readiness only with correctness evidence; keep functional results separate from performance results.
5. **Establish publication evidence.** Use strict preflight and CPU isolation, preserve image digests and host metadata, audit security profiles against the HHE-128 rules, and repeat comparable workloads under a documented protocol.
6. **Publish a reproducible release.** Publish immutable image digests, fill catalog pull references, document supported platforms and exclusions, and provide a repeatable framework integration template. Freeze matrix v2 only after its release scope passes the criteria above.

## Known blockers

- **BtR:** checked-in extension and compatible pinned Lattigo revisions disagree on required APIs; the Linux CPU call also needs migration.
- **FiLIP/Rust reference:** required upstream branch is unavailable.
- **YuX HElib:** dependency build uses an unpinned HElib branch and source builds during image creation.
- **Publication host:** the native Linux functional run did not confirm RDTSCP, a uniform performance governor, or Turbo state.
